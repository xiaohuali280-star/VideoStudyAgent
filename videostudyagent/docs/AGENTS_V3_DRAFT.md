## 2. 建议新增的审核与来源规则

1. Critic 为普通 ReviewService，不具有独立目标、自主工具循环、数据库权限或单独预算。最多一次自动定向重做，共用既有 BoundedLLM 和超时；语义审核故障不伪装成通过。
2. 来源检查区分字幕/ASR 和 OCR。OCR 引用指向真实帧时刻、原识别文本和帧 ID；不能伪造字幕、不能按序号估算时间、不能把 OCR 文本原样匹配当像素识别正确或语义蕴涵证明。
3. Transcript 保持原始精确区间，VideoContext 独立快照。未选章节、旧版本、旧批次不改写；来源、审核和索引均冻结到具体 snapshot/document hash。
4. 新审核结果为 passed/failed/uncertain；新正式结果默认在审核通过后发布，失败/不确定保留原正式版本。原历史资料保持可读，明确显示是否曾审核，不追溯付费审核。
5. 整课笔记继续全量分块；TopK 检索只服务问题定位和补证。检索只访问服务端确认的同课程同快照，不因索引故障扩大范围。
6. 图片留本机；OCR 是可选本地能力。未来多模态生成界面应明确说明：启用时识别文字会作为课程数据传给已选择的 LLM；原始帧图片不会自动上传。任何新增云端视觉服务另行确认。
7. 默认评测 fixture/replay，不在服务启动、上传、测试或评测中隐式读生产 Key、调用真实模型。指标必须带样本量、执行范围和未验证状态；人工质量与供应商计费不能用替身值代替。
8. 本地 Tesseract、语言包、图像依赖或 Embedding 模型只在获批阶段显式准备；不自动下载大模型。版本、许可证和来源在实际采用时登记。
