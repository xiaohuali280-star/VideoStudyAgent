# VideoStudyAgent 第二轮功能迭代计划

初稿：2026-10-13；更新：2026-10-14（Asia/Shanghai）。状态：阶段 8–14 已完成实现和离线验收；9–13 已逐阶段上传，14 验收后上传。详见各阶段报告。没有迁移用户数据库或调用真实云端模型。

本文件作为未来 Codex 的执行依据。原 MVP 及阶段 1–7 的历史约定保存在根目录 PLAN.md；本轮涉及产品行为变更时，以用户最新要求及本文为准。每次只实施一个阶段，测试和报告后再继续。

## 1. 已确认需求与边界

1. **字幕读取保持自动执行，不增加关闭字幕读取的开关。** 用户自主选择是否梳理笔记、是否生成自测；已有有效字幕结果可复用。
2. 课程笔记页面增加聊天框，支持解释、分析、调整笔记偏好及生成修改草稿；聊天回复与正式笔记分别保存。
3. 移除题数选择入口，新生成的自测每批固定 5 道简答题，保留难度选择，提供“换一批”。

继续采用 React/FastAPI/SQLite、独立单 Worker、单 Agent + Tool Calling。保持字幕优先、毫秒来源、严格输出校验和既有导出。暂不引入多 Agent、OCR、RAG/向量库、认证、自动评分、自由富文本编辑器或部署。

不修改本地 API Key、时长配置或现有模型预算。当前每次尝试的 500000 保守 token 预算保持不变；规划及离线测试不调用真实模型。真实调用须另行落实预算，不以提高默认上限解决长课程问题。

## 2. 当前实现与必须改动的依赖

本轮核查的现有文件：

- backend/app/schemas/study.py：StudyOptions 冻结，题数允许 1–20；Question.chapter_id 必填。
- backend/app/agent/tools.py：generate_quiz 同时要求 transcript/notes；complete() 强制三种产物全部存在；初始化就建立生成服务。
- backend/app/task_runner.py：处理前创建 LLM；无法在无 Key 时只解析字幕。
- backend/app/services/generation.py：笔记和出题共用预算，出题依赖笔记章节；完整笔记成功后才缓存，缺少逐块检查点。
- backend/app/services/exports.py、api.py：成功条件与重试校验仍假定三种产物齐全。
- backend/app/db/models.py：ArtifactRow 对 task_id/kind 唯一，只适合当前结果，不适合保存笔记历史和多批自测。
- frontend/src/components/UploadForm.tsx：当前实际题数选择为 1–20，需要按新要求移除。
- TaskView/NotesViewer/QuizViewer：流程阶段固定，无聊天、版本管理或换批入口。

因此本轮不能只增加前端按钮：任务完成条件、工具权限、出题来源、数据版本、缓存和恢复规则必须一起调整。

## 3. 产品行为

### 3.1 可选笔记与自测

首次上传默认同时启用笔记、自测，保持原来的主要使用路径。字幕解析/语音转写始终是前置步骤：有字幕优先解析字幕；仅视频则提取音频并转写；已有有效结果可复用。

| 梳理笔记 | 生成自测 | 实际工作 | 成功所需结果 |
| --- | --- | --- | --- |
| 关闭 | 关闭 | 仅准备字幕 | transcript |
| 开启 | 关闭 | 字幕 → 笔记 | transcript + notes |
| 关闭 | 开启 | 字幕 → 5 道题，不隐式生成笔记 | transcript + quiz |
| 开启 | 开启 | 字幕 → 笔记 → 5 道题 | transcript + notes + quiz |

- 只准备字幕时不创建 LLM 客户端、不运行模型调度，不要求 DeepSeek Key；视频仍要求本地媒体/转写依赖。
- 关闭功能表示本次不执行，不能删除此前已有的笔记或自测。
- 关闭的阶段显示“未启用”，不要作为永久“待处理”或错误。
- 用户可在已保存课程中补生成笔记或自测，无需重新上传或重复转写。
- 任务提交时冻结开关、难度、语言、偏好和输入版本；运行中修改设置只影响下一次操作。
- 服务器独立限制工具集合与完成条件；提示词之外必须有后端权限检查，模型不能自行开启关闭的功能。
- 部分成功的结果继续可读、可导出；后续步骤失败不删除已完成内容。

### 3.2 笔记聊天、偏好与修改

桌面端笔记与聊天并排，手机端采用可切换面板。没有笔记时提示先生成笔记；不自动产生一次付费生成。聊天按课程保存，刷新可恢复。

先实现“分析”，再实现“修改”：

| 用户操作 | 系统行为 | 是否改变正式笔记 |
| --- | --- | --- |
| “解释这个章节”“帮我比较这两个概念” | 基于选定笔记版本、章节及相关字幕回答，附有效来源 | 否 |
| “以后这门课的笔记简洁一点” | 提出可核对的偏好变更；用户保存课程偏好 | 否 |
| 点击“按偏好生成草稿”或明确要求改写 | 对选定章节/整份笔记生成新草稿，保留来源 | 否 |
| “应用此版本” | 校验草稿及基准版本后切换当前笔记 | 是，不再次调用模型 |
| “放弃草稿”或“恢复此版本” | 放弃草稿或切换到已验证历史版本 | 仅用户明确操作时切换 |

建议偏好字段：详略程度（简洁/标准/详细）、组织方式（提纲/讲解/复习）、是否增加例子、是否突出公式、重点主题、自定义要求。首版只做课程级偏好；跨课程全局默认偏好留待后续，不引入用户体系。

保存偏好不自动重写笔记，也不自动更新自测。聊天中识别出的偏好只是建议，必须经过字段白名单和用户确认；不能变更工具权限、预算、路径或密钥配置。

章节改写以冻结的完整笔记为基准，只合并用户选定章节的变化；保留未选章节及其 ID，合并后再验证整份笔记的来源覆盖。不能用一段聊天回复替换整份 NotesDocument，或因为局部改写丢掉其他章节。草稿预览至少显示改动章节与前后内容；正式笔记不直接接受任意聊天 Markdown 写入。

上下文规则：

- 默认发送选定章节、相关原始字幕和有限最近对话；保留完整本地消息历史，但不每轮发送全部历史。
- 用章节 source_segment_ids 找原始片段，不引入向量检索或 RAG。跨章节问题由用户选择范围。
- 整课请求超过预算时明确提示选择章节或启动有进度的分块操作，不静默截断课程。
- 回复中的课程事实附原文引用；补充解释标注为模型解释。来源匹配不能替代语义质量检查。
- 生成时固定 notes_revision_id；用户切换版本后，已有消息仍注明原来的上下文版本。
- 用户文本、字幕及笔记是数据；前端不能提交 system/tool 角色，不能提供任意文件路径或其他课程 ID。
- 首版采用排队状态与轮询，不做流式输出。单 Worker 忙于其他操作时显示等待；优先级只能影响尚未领取的操作，不能承诺立即打断正在运行的课程。

### 3.3 固定 5 题与换一批

- 上传表单移除题数输入，开启自测时显示“每批 5 道简答题”；关闭自测用开关表达，不用 0 题表达。
- 首次生成与换批均由服务端固定为 5；不足 5、超过 5、缺答案/解析/引用均不能发布。
- 保留 easy/medium/hard。换批默认沿用当前难度及资料语言，每次提交冻结参数。
- 点击“换一批（5题）”建立独立生成操作，新批次完成且全部校验通过后才切换显示。
- 等待/失败期间保持旧批次可读、可导出，不先清空旧题。
- 防止双击、刷新或客户端网络重发创建重复付费操作：请求具备幂等键；同键同参数返回同一操作，同键不同参数返回冲突。
- 新一批使用新 batch_id/nonce，重试同一批沿用原 ID；缓存键包含批次与来源快照，不能反复返回旧批题目。
- 提示只携带最近少量题干作为排除项；服务器用全部历史题干归一化 hash 检查直接重复，避免历史不断撑大提示。
- 排除当前/历史的直接重复；不同措辞的语义重复首版只能尽力减少，不宣称算法严格保证。材料不足或连续校验失败时有限重试后提示，禁止无限换题循环。
- 历史批次可切换，导出与页面所选批次一致；每批记录依赖的字幕与笔记版本。
- 笔记后来修改不使旧题静默改变，也不自动重生成；显示题目所基于的版本，用户可主动换批。
- 旧任务已经生成的 1–20 题结果保持可读、可导出；只有新生成的批次固定 5。

## 4. 技术方案与数据契约

### 4.1 保留主架构，增加独立操作记录

沿用现有 task_id 作为课程标识，避免一次性重命名全库与全部 API。增加 StudyOperation 表示“对这门课程执行一次操作”，将课程资料与后续操作的状态分开。

操作类型：initial_study、generate_notes、generate_quiz、chat_reply、revise_notes。状态保持 queued/running/succeeded/failed，增加明确 cancelled 语义。失败操作不把原本可用的课程结果清空。

所有模型相关操作进入同一独立 Worker 队列，不在 HTTP 请求中执行长生成。只准备字幕的操作直接调用业务服务，无模型调度；需要生成时继续使用一个受限 Agent，普通聊天/生成调用不是另一个 Agent。

Worker 最终只领取一种 Operation 队列，不能长期维护两个相互竞争的队列。为原 Task 队列做兼容适配与一次性迁移；原 Task.status 仅映射初始处理，前端另显示后续操作状态。

### 4.2 建议模型

| 模型 | 必要字段与规则 |
| --- | --- |
| ProcessingOptions | generate_notes、generate_quiz；服务端总是准备/复用 transcript；默认两个 true |
| StudyOperation | id、task_id、kind、status、attempt、幂等键/请求摘要、冻结参数、输入快照、基准笔记版本、输出引用、错误、时间、预算/用量摘要 |
| TranscriptSnapshot | id、task_id、storage_key、sha256、schema_version；不可变，保留真实毫秒来源 |
| NotePreferences | 课程 ID、revision、详略/结构/例子/公式/主题/自定义要求；有长度与数量限制 |
| NotesRevision | id、task_id、parent/base_revision_id、source_transcript_snapshot_id、preferences_snapshot、草稿/已发布状态、内容文件/哈希、创建操作 |
| QuizBatch | id、task_id、sequence、source_transcript_snapshot_id、notes_revision_id 可空、固定 5 题参数、nonce、文档/哈希、创建操作 |
| Conversation / ConversationMessage | 课程内会话、消息序号、user/assistant 角色、内容、来源引用、上下文版本、操作 ID、状态；消息顺序与发送幂等 |
| CourseStudyState | 当前笔记版本与当前自测批次指针、字幕快照、功能选项；摘要 DTO，可由现有课程数据与关联表组成 |

操作状态、消息元数据和版本索引存 SQLite；版本化结果继续存本地不可变 JSON，复用 ArtifactStore 的安全路径、哈希校验和原子写入。

现有 ArtifactRow 的 task_id/kind 唯一约束只保留为旧接口的当前结果投影，不用它承载全部版本。新快照与版本不能外键绑定到会被替换/删除的旧 ArtifactRow；保存自己的不可变文件引用和哈希。

### 4.3 出题解除笔记依赖

新版问题的 source_segment_ids/evidence 始终必填；chapter_id 改为可空。有笔记时可引用被冻结的笔记版本章节，无笔记时直接引用字幕片段与时间。

GenerationService.generate_quiz 和工具参数改为 transcript 必需、notes 可选；禁止为满足 chapter_id 偷偷生成一份隐藏笔记。跨文档校验根据是否存在笔记选择规则，但不能放宽 quote 原文匹配、题数、难度及答案解析要求。

新文档使用显式新 schema_version（建议 1.1），旧 1.0 文件通过适配器读取，不就地改写或改变原 hash。旧 QuizDocument/StudyOptions 不直接收紧到 5，以免已有 1/20 题记录无法读取；新请求单独使用固定 5 的 QuizGenerationOptions，非 5 输入明确拒绝。

### 4.4 API 草案

保持已有上传、查询与导出地址；增加功能路由，命名可在阶段 8 固定：

| 接口 | 用途 |
| --- | --- |
| POST /api/tasks | options 增加两个开关，创建课程与 initial_study 操作 |
| GET /api/tasks/{id}/study-state | 当前资料/版本/批次及操作摘要，避免拿单一 task.status 表达全部状态 |
| POST /api/tasks/{id}/operations | 补生成笔记、自测或草稿；按 kind 严格校验参数 |
| GET /api/tasks/{id}/operations/{operation_id} | 轮询及预算/失败摘要 |
| POST .../operations/{operation_id}/retry 或 /cancel | 重试/取消，不接受其他课程的操作 ID |
| GET /api/tasks/{id}/quiz-batches | 批次列表及读取指定批次 |
| POST /api/tasks/{id}/quiz-batches | 首批/换一批，固定 5，支持幂等键 |
| GET/POST /api/tasks/{id}/chat/messages | 读取消息；发送消息后返回 202 + operation_id |
| GET/PUT /api/tasks/{id}/note-preferences | 读取/保存偏好，有 revision 防覆盖 |
| GET /api/tasks/{id}/notes/revisions | 查看版本与草稿 |
| POST /api/tasks/{id}/notes/revisions/{revision_id}/apply | 确认应用/恢复，检查 expected_current_revision_id |
| GET /api/tasks/{id}/exports/{format} | 可选 notes_revision_id / quiz_batch_id；缺省使用当前正式版本 |

所有 UUID 都验证课程归属；文件路径由服务端生成。写接口不接受客户端自定义预算、服务地址、模型 Key 或权限。OpenAPI 与前端生成类型同时更新。

### 4.5 预算、检查点与并发

- 维持当前请求、输入/输出、工具次数和总预算限制；聊天每轮有较小上下文/输出上限，不自动扩大 500000。
- 界面显示保守预留与供应商返回用量的区别；真实用量未知时标未知，不当作 0，不把 token 数转换为未经核实的金额。
- 初始处理、换批、聊天、改写分别记录每次尝试的预算与用量。增加课程累计摘要，防止多次独立操作掩盖累计使用；本轮不承诺货币金额硬上限。
- 执行前做分块/请求数量预检；若正常路径的最低预留已超限，尽早提示分段或缩小范围，不先消耗一半预算才失败。
- 每个已校验笔记块写检查点。键包含字幕 hash、片段/分块 hash、模型、提示版本、语言、偏好、上下文策略；修复失败的块不缓存。
- 重试复用合法检查点，并重新校验内容和来源；损坏块只重做对应块，不重做已经成功的全课。不得把部分笔记伪装成完整笔记。
- 重试的新尝试仍受相同预算；累计用量跨尝试保留。不得在一次操作中通过偷偷重置计数器绕过上限。
- 同一课程的写操作用串行约束及版本比较，幂等提交采用事务/唯一约束；旧草稿基准过期时返回 409，不覆盖新的正式笔记。
- 取消必须传播到 Worker 自有任务进程，不只是修改数据库。已保存结果保留；对请求发出前/生成中/发布前的取消分别测试，不能把可能已经计费的请求说成未消费。
- 只按“同一课程正在更新”加锁，不让读取笔记/旧批次依赖生成事务；模型调用不持有数据库事务。

### 必测场景

1. 仅字幕模式，即使没配置 LLM Key，也成功解析并下载字幕。
2. 关闭笔记、开启自测，只生成字幕和 5 题；不存在隐藏笔记或额外笔记调用。
3. 开启笔记、关闭自测，笔记完成即操作成功，页面不永久等待自测。
4. 换批生成超时/预算不足时，上一批 5 题及其导出仍可使用。
5. 聊天解释和保存偏好不改正式笔记；明确应用草稿后导出对应新版本。
6. 旧版本聊天/自测保持原来源，不能随着当前笔记指针变化偷偷改文档。
7. 生成中刷新、取消、重启或请求重发不会造成重复队列或发布半份结果。
8. 超长课程只允许有提示的分段/缩小范围；预算和来源要求不能因聊天或换批放宽。

## 7. 数据迁移与交付规则

- 仅在实施阶段、停止旧 Worker 并协调 API 写入后执行迁移。先用 SQLite 备份接口或完整停机备份保护 DB/WAL 一致性，备份与用户内容只存本地忽略目录。
- 在临时测试库验证旧任务、有效产物、失败记录、旧题数及队列适配；为旧笔记/自测建立初始版本/批次索引，不改写原 JSON 或哈希。
- 初始操作迁移具备唯一映射；中断的 running 状态标为可恢复，不自动重新付费执行。
- 已有结果文件需要保留，清理工具不能将历史版本/批次误判为孤立文件删除。
- 原始阶段报告保持历史事实，本轮另写 STAGE_8_REPORT.md 至 STAGE_14_REPORT.md。
- 每阶段报告：范围、修改文件、实际测试、复用变化、遗留问题；不能把未运行的测试或替身响应当成真实模型通过。
- 2026-10-14 用户已新增授权继续实现并上传 GitHub；阶段 8 独立测试报告后上传。后续继续每次一个阶段；不部署，不修改本地密钥、预算或用户数据库。
